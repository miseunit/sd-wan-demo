## 二、架构决策记录

### 2.1 为什么用 CSS 变量而不是 CSS-in-JS？

**决策：** 使用 CSS 变量（`var(--xxx)`）管理样式。

**原因：**
- CSS 变量是浏览器原生的，不需要额外运行时开销
- 切换主题时只需要改变量值，所有组件自动更新
- 代码更简单，不需要 `styled-components` 或 `emotion` 的学习成本
- 调试方便，浏览器 DevTools 可以直接查看和修改变量值

**替代方案：**
- CSS-in-JS（styled-components）— 运行时开销大
- Tailwind CSS — 类名太长，主题切换不方便
- CSS Modules — 主题切换需要额外处理

---

### 2.2 为什么用 React Context 而不是 Redux？

**决策：** 使用 React Context 管理全局状态。

**原因：**
- 项目规模不大，只有主题和认证两个全局状态
- Context 是 React 内置的，不需要额外依赖
- 代码更简单，不需要 action/reducer/store 的模板代码

**替代方案：**
- Redux — 太重，适合大型应用
- Zustand — 轻量但仍然是外部依赖
- Jotai/Recoil — 原子化状态，对这个项目来说过度设计

---

### 2.3 为什么用 SQLite 而不是 PostgreSQL？

**决策：** 开发环境用 SQLite，生产环境可切换 PostgreSQL。

**原因：**
- SQLite 不需要安装，文件级数据库
- 开发环境快速启动，零配置
- SQLAlchemy 支持多种数据库，切换成本低
- Demo 项目数据量不大，性能够用

**切换到 PostgreSQL：**
```python
# 修改 .env
DATABASE_URL=postgresql://user:password@localhost:5432/sdwan

# 安装驱动
pip install psycopg2-binary
```

---

### 2.4 为什么用 FastAPI 而不是 Django/Flask？

**决策：** 使用 FastAPI 作为后端框架。

**原因：**
- 自动生成 API 文档（Swagger UI）
- 原生支持异步（async/await）
- Pydantic 数据校验，类型安全
- 性能好（基于 Starlette/Uvicorn）
- 代码简洁，学习成本低

**替代方案：**
- Django — 太重，有很多不需要的功能（admin、template）
- Flask — 没有自动文档、没有数据校验

---

### 2.5 为什么用统一响应格式？

**决策：** 所有 API 返回 `{code, message, data}` 格式。

**原因：**
- 前端可以统一处理响应，不需要每个接口单独处理
- 错误处理一致，前端只需检查 `code` 字段
- 方便日志记录和调试
- 方便 API 网关统一处理

**前端自动解包：**
```javascript
// api.ts 中自动解包
if (rawData.code && rawData.message) {
    return rawData.data;  // 前端直接拿到数据
}
```

---

### 2.6 为什么用 Vite 而不是 Webpack？

**决策：** 使用 Vite 作为前端构建工具。

**原因：**
- 开发服务器启动极快（毫秒级）
- 热更新极快（只更新修改的模块）
- 配置简单（vite.config.ts 只有几行）
- 原生支持 ESM（ES Modules）

**替代方案：**
- Webpack — 启动慢、配置复杂
- Parcel — 零配置但灵活性不够

---

### 2.7 为什么前端用 fetch 而不是 axios？

**决策：** 使用原生 fetch + 自己封装。

**原因：**
- 浏览器原生 API，不需要额外依赖
- 项目只需要基本的 GET/POST/PUT/DELETE
- 自己封装可以完全控制行为（去重、刷新 token 等）
- 包体积更小

**替代方案：**
- axios — 功能多但项目用不到（拦截器、取消请求等）
- ky — 轻量封装但仍然是外部依赖

---

### 2.8 为什么每个页面一个文件夹？

**决策：** 每个页面有独立的文件夹，包含组件、样式、类型、API。

**原因：**
- 页面相关的代码放在一起，容易找到
- 删除页面时只需删除一个文件夹
- 样式不会互相污染（每个页面有自己的 CSS 文件）
- 团队协作时减少冲突

**文件夹结构示例：**
```
pages/SiteManagement/
├── SiteManagement.tsx    ← 主组件
├── SiteManagement.css    ← 样式
├── SiteFormModal.tsx     ← 弹窗组件
├── types.ts              ← 类型定义
└── index.ts              ← 导出入口
```
