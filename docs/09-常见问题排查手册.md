# SD-WAN 管理平台 — 常见问题排查手册

> **遇到问题先看这份文档，90% 的问题都能在这里找到答案。**

---

## 一、前端问题

### 1.1 页面白屏

**可能原因：**

1. **组件导入路径错误**
   - 检查 `import` 路径是否正确
   - 检查文件名大小写是否匹配

2. **组件没有正确导出**
   - 确保有 `export default` 或 `export`

3. **路由配置错误**
   - 检查 `App.tsx` 中的路由路径
   - 检查组件是否正确导入

4. **JavaScript 报错**
   - 打开浏览器 F12 → Console，看红色错误信息

**排查步骤：**
```
1. 打开浏览器 F12
2. 看 Console 有没有红色报错
3. 看 Network 有没有请求失败（红色）
4. 根据报错信息定位问题
```

---

### 1.2 样式不生效

**可能原因：**

1. **CSS 文件没有被 import**
   - 确保在组件中有 `import './XXX.css'`

2. **类名拼写错误**
   - 检查 CSS 中的类名和 JSX 中的 `className` 是否一致

3. **CSS 变量没有定义**
   - 检查 `src/index.css` 中是否定义了对应的变量

4. **被其他样式覆盖**
   - 用浏览器 F12 → Elements → 检查元素的样式
   - 看是否有被划掉的样式（被覆盖了）

5. **Ant Design 样式优先级更高**
   - 需要用 `!important` 覆盖

---

### 1.3 深色/浅色主题切换不生效

**排查步骤：**
```
1. 检查 ThemeProvider 是否在 main.tsx 中包裹了应用
2. 检查 HTML 标签上是否有 data-theme 属性
3. 检查 CSS 变量是否在 [data-theme="dark"] 和 [data-theme="light"] 中都有定义
4. 检查组件中是否用了 var(--xxx) 而不是硬编码颜色
```

---

### 1.4 API 请求失败

**排查步骤：**
```
1. 检查后端是否启动（访问 http://localhost:8000/health）
2. 检查 vite.config.ts 中的代理配置
3. 检查请求路径是否正确（应该以 /api/v1 开头）
4. 打开 F12 → Network，看请求的状态码
   - 404: 路径错误
   - 500: 后端报错
   - CORS: 跨域配置问题
```

---

### 1.5 表格不显示数据

**排查步骤：**
```
1. 检查 dataSource 是否有数据（console.log 打印）
2. 检查 rowKey 是否正确设置
3. 检查 columns 中的 dataIndex 是否跟数据字段名一致
4. 检查数据格式是否正确（应该是数组）
```

---

### 1.6 弹窗不弹出

**排查步骤：**
```
1. 检查 open 属性是否正确绑定（应该是 boolean）
2. 检查点击事件是否正确触发（console.log 测试）
3. 检查 Modal 组件是否正确导入
4. 检查是否有 z-index 被其他元素遮挡
```

## 二、后端问题

### 2.1 后端启动报错

**ModuleNotFoundError: No module named 'xxx'**
```bash
# 确保虚拟环境已激活
.venv\Scripts\activate  # Windows
source .venv/bin/activate  # Mac/Linux

# 重新安装依赖
pip install -r requirements.txt
```

**sqlalchemy.exc.OperationalError: unable to open database file**
```bash
# 检查 data 目录是否存在
mkdir -p backend/data

# 检查 DATABASE_URL 路径是否正确
# 应该是 sqlite:///./data/app.db
```

---

### 2.2 API 返回 422 错误

422 是参数校验失败。检查：
- 请求参数类型是否正确（int 还是 string）
- 必填参数是否都传了
- 参数名是否拼写正确

---

### 2.3 API 返回 500 错误

500 是服务器内部错误。查看后端终端的报错信息：
```bash
# 后端终端会打印详细的错误堆栈
# 根据堆栈信息定位问题
```

常见原因：
- 数据库表不存在（删除 data/app.db 重新启动）
- 代码语法错误
- 数据类型不匹配

---

### 2.4 数据库被锁

```
sqlite3.OperationalError: database is locked
```

原因：多个进程同时写数据库。

解决：
```bash
# 关闭所有后端进程，只保留一个
# 或者换用 PostgreSQL
```

---

### 2.5 种子数据没有填充

**排查步骤：**
```
1. 检查 seed.py 中的 seed_all 函数
2. 检查是否已有数据（如果有数据会跳过填充）
3. 删除 data/app.db 重新启动
```

## 三、前后端对接问题

### 3.1 跨域错误 (CORS)

**浏览器报错：** `Access to fetch at 'http://localhost:8000/api/v1/sites' from origin 'http://localhost:5173' has been blocked by CORS policy`

**解决：**
```python
# 后端 main.py 中确保有 CORS 配置
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173"],  # 包含前端地址
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

或者配置 Vite 代理（推荐）：
```typescript
// vite.config.ts
server: {
    proxy: {
        '/api': {
            target: 'http://localhost:8000',
            changeOrigin: true,
        },
    },
},
```

---

### 3.2 响应格式不对

**期望：** `{ code: 200, message: "成功", data: {...} }`
**实际：** `{ id: 1, name: "xxx" }`（没有包装）

**解决：** 检查后端是否使用了 `success()` 函数包装响应。

---

### 3.3 数据字段名不匹配

**后端返回：** `{ display_name: "北京" }`
**前端期望：** `{ displayName: "北京" }`

**解决：** 后端在返回数据时转换字段名（snake_case → camelCase），或者前端适配后端的字段名。

## 四、部署问题

### 4.1 前端 build 失败

```bash
# 清除缓存重试
rm -rf node_modules
npm install
npm run build
```

### 4.2 Nginx 配置后刷新 404

```nginx
# 需要配置 try_files
location / {
    try_files $uri $uri/ /index.html;
}
```

### 4.3 生产环境 API 请求失败

检查 Nginx 的 proxy_pass 配置是否正确：
```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8000;
}
```

## 五、开发工具问题

### 5.1 VS Code 中 TypeScript 报错

```
Cannot find module 'xxx' or its corresponding type declarations
```

**解决：**
```bash
# 安装类型声明
npm install @types/xxx

# 或者在文件顶部加注释忽略
// @ts-ignore
```

### 5.2 ESLint 报错

```bash
# 自动修复
npm run lint -- --fix
```

### 5.3 热更新不生效

```
修改代码后浏览器没有自动刷新
```

**解决：**
- 检查终端是否显示 `hmr update` 日志
- 手动刷新浏览器（F5）
- 重启开发服务器（Ctrl+C 后重新 `npm run dev`）

## 六、性能问题

### 6.1 页面加载慢

- 检查是否有大量数据一次性加载（应该分页）
- 检查是否有图片没有压缩
- 检查是否有不必要的 re-render（用 React DevTools）

### 6.2 API 请求慢

- 检查数据库查询是否有索引
- 检查是否有 N+1 查询问题
- 检查是否有大量数据没有分页

### 6.3 内存泄漏

- 检查 useEffect 中是否有定时器没有清除
- 检查是否有事件监听没有移除
- 检查 WebSocket 连接是否正确关闭

---

## 七、快速排查清单

遇到问题时，按这个顺序排查：

```
1. 看浏览器控制台（F12 → Console）
   → 有红色报错？根据报错信息定位

2. 看网络请求（F12 → Network）
   → 有请求失败？看状态码和响应内容

3. 看后端终端
   → 有错误堆栈？根据堆栈定位

4. 检查代码
   → import 路径对不对？
   → 变量名拼写对不对？
   → 函数调用参数对不对？

5. 重启试试
   → 停止前后端，重新启动
   → 清除浏览器缓存（Ctrl+Shift+Delete）
   → 删除 node_modules 重新 npm install
   → 删除 data/app.db 重新启动后端
```
