## 四、入口文件 main.tsx

入口文件是第一个被执行的文件，它的职责是：
1. 引入全局样式
2. 配置 Provider（主题、路由、Ant Design 配置）
3. 渲染 App 组件

**Provider 包裹顺序（从外到内）：**

```
ThemeProvider          ← 主题管理（最外层）
  └─ BrowserRouter     ← 路由功能
       └─ ConfigProvider  ← Ant Design 主题配置
            └─ AuthProvider    ← 登录状态管理
                 └─ App         ← 路由和页面
```

**为什么是这个顺序？**
- ThemeProvider 在最外层，所有组件都能访问主题
- BrowserRouter 包裹所有路由相关组件
- ConfigProvider 需要读取主题来配置 Ant Design
- AuthProvider 在 ConfigProvider 里面，因为登录弹窗需要用 Ant Design 组件

## 五、路由配置 App.tsx

路由配置决定哪个网址显示哪个页面。

**路由结构：**

```
/login          → Login（公开路由，不需要登录）
/register       → Register（公开路由）
/               → Home（需要登录，嵌套在 AppLayout 中）
/sites          → SiteManagement
/links          → LinkManagement
/devices        → DeviceManagement
/policy         → PolicyManagement
/alerts         → AlertCenter
/topology       → TopologyView
/dashboard      → Dashboard
/settings       → SystemSettings
```

**路由守卫：**
- `PublicRoute` — 已登录用户访问登录页时，自动跳转到首页
- `ProtectedRoute` — 未登录用户访问管理页时，自动跳转到登录页

## 七、状态管理

### 7.1 用 React Context 管理全局状态

这个项目用 React Context 管理两个全局状态：

| Context | 状态 | 提供的方法 |
|---------|------|-----------|
| `ThemeContext` | 当前主题（dark/light） | `toggleTheme()` |
| `AuthContext` | 用户信息、登录状态 | `login()`, `logout()`, `getCurrentUser()` |

### 7.2 什么时候用 Context？

**用 Context：**
- 多个页面都需要的状态（如主题、登录状态）
- 跨层级传递的状态（如从顶层到底层组件）

**不用 Context：**
- 只在一个页面用的状态 → 用 `useState`
- 只在父子组件之间传递 → 用 props

### 7.3 页面内部状态

每个页面自己的状态用 `useState` 管理：

```tsx
const [data, setData] = useState([]);           // 表格数据
const [loading, setLoading] = useState(false);   // 加载状态
const [search, setSearch] = useState('');         // 搜索关键词
const [modalOpen, setModalOpen] = useState(false); // 弹窗开关
const [editing, setEditing] = useState(null);     // 当前编辑的记录
```

## 九、API 对接方式

### 9.1 统一请求封装 services/api.ts

所有 API 请求都通过 `api.ts` 封装的函数发起：

```tsx
import { get, post, put, del } from './api';

// GET 请求
const data = await get('/sites/?page=1&pageSize=10');

// POST 请求
await post('/sites/', { name: '新站点', region: 'CN' });

// PUT 请求
await put('/sites/site-01', { displayName: '新名称' });

// DELETE 请求
await del('/sites/site-01');
```

### 9.2 api.ts 做了什么？

1. **统一基础路径** — 自动加 `/api/v1` 前缀
2. **自动加 Token** — 请求头自动带 `Authorization: Bearer xxx`
3. **统一解包响应** — 后端返回 `{code, message, data}` → 前端直接拿到 `data`
4. **错误处理** — 非 200 状态码抛出异常
5. **Token 过期自动刷新** — 401 时自动用 refresh_token 换新 token
6. **请求去重** — 同一个 GET 请求不会发两次
7. **超时控制** — 30 秒超时自动中断

### 9.3 每个模块的 API 文件

每个业务模块有自己的 API 文件，封装该模块的所有接口：

```tsx
// services/siteApi.ts
import { get, post, put, del } from './api';

export function getSites(params) {
    return get(`/sites/?${new URLSearchParams(params)}`);
}
export function getSite(id) { return get(`/sites/${id}`); }
export function createSite(data) { return post('/sites/', data); }
export function updateSite(id, data) { return put(`/sites/${id}`, data); }
export function deleteSite(id) { return del(`/sites/${id}`); }
```

### 9.4 页面中调用 API

```tsx
import { getSites, createSite, deleteSite } from '../../services/siteApi';

// 加载数据
const loadData = async () => {
    setLoading(true);
    try {
        const result = await getSites({ page: 1, pageSize: 10 });
        setData(result.items);
        setTotal(result.total);
    } catch (error) {
        message.error(error.message);
    } finally {
        setLoading(false);
    }
};
```

## 十、样式组织方式

### 10.1 样式文件分布

| 文件 | 内容 |
|------|------|
| `src/index.css` | CSS 变量定义 + 全局基础样式 |
| `src/styles/theme.css` | 通用组件样式（表格、分页、按钮、卡片、状态标签等） |
| `src/layouts/AppLayout.css` | 布局样式 |
| `src/pages/XXX/XXX.css` | 页面专属样式 |
| `src/components/XXX/XXX.css` | 组件专属样式 |

### 10.2 CSS 类命名规范

采用 BEM 命名法的简化版：

```
.block                    → 块
.block__element           → 块内的元素
.block--modifier          → 块的修饰状态
.block__element--modifier → 元素的修饰状态
```

示例：
```css
.app-sidebar              { }  /* 侧边栏 */
.app-sidebar__brand       { }  /* 侧边栏的品牌区 */
.app-sidebar--collapsed   { }  /* 折叠状态的侧边栏 */
.app-menu-item            { }  /* 菜单项 */
.app-menu-item--active    { }  /* 激活状态的菜单项 */
.app-menu-item__icon      { }  /* 菜单项的图标 */
```

### 10.3 样式优先级

1. CSS 变量（`var(--xxx)`）— 颜色、阴影等
2. 页面专属 CSS — 布局、特殊样式
3. 通用样式（theme.css）— 表格、分页、按钮等
4. Tailwind CSS — 辅助工具类（可选）

## 十二、开发流程

### 12.1 新建一个页面的步骤

```
1. 创建文件夹 pages/XXXManagement/
2. 创建 index.ts（导出入口）
3. 创建 XXXManagement.tsx（主页面）

```

### 12.2 开发顺序

```
第 1 步：搭骨架（页面结构 + 占位内容）
第 2 步：做静态 UI（用假数据把页面做出来）
第 3 步：对接 API（替换假数据为真实数据）
第 4 步：做交互（增删改查、筛选、排序）
第 5 步：打磨细节（loading、空状态、错误提示、动画）
```

## 十三、常见问题

### Q: 混用 JS 和 TS 文件怎么办？

项目中有些文件是 `.jsx`（纯 JS），有些是 `.tsx`（TS）。在 TS 文件中引用 JS 文件时，需要加注释：

```tsx
// @ts-ignore - JSX module
import SomeComponent from './SomeComponent.jsx';
```

### Q: CSS 不生效怎么办？

1. 检查文件是否被 import
2. 检查类名是否拼写正确
3. 检查是否被其他样式覆盖（优先级问题）
4. 检查 CSS 变量是否在 index.css 中定义

### Q: 组件不渲染怎么办？

1. 检查是否正确导出（`export default`）
2. 检查 import 路径是否正确
3. 检查路由配置是否正确
4. 打开浏览器控制台看报错
